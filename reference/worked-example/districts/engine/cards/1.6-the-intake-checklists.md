# 1.6 · The Intake Checklists

**Type + State:** ENGINE · LIVE — the routing table names one checklist each for Listing, Matching
and Showing notes (`rules.md:27-30`), and `rules.md:9` sends any job with missing inputs to a
checklist: "Never invent inputs."

**What it is:** what the specialist asks before it works. Two are true intakes; the third,
`showing-intake.md`, is the whole procedure of the Showing notes job, filed among them.

**Why it is shaped that way:** a missing input is the step where a model guesses, so each job's
questions are fixed in a file and asked before any output.

**Source path:** `specialist/reference/checklists/`

**Hits:** every market's runs of the jobs that use them, at the start of the run — and one job the
table does not list: Pricing has no checklist in its routing row, yet `frameworks/pricing.md:15`
sends missing pricing inputs to `listing-intake.md`.

**Does not hit:** the shape of the answer. A reader who wants a new section in a listing edits
`listing-intake.md`; that changes what is asked, not what comes back, which is card 1.5.

**Done when:** you know which jobs ask from the checklist you are changing — Pricing included for
`listing-intake.md` — and you have not opened a template. Stop there.
